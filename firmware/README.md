# 硬件固件 — 四条链路

ESP32-S3 手表硬件 bring-up。四条链路全部跑通：**录音 / 放音 / 心率 / 体温**。

这是硬件验证阶段的代码，目的是确认每个模块接线正确、能出数，**不是最终产品固件**。

---

## 硬件

| 模块 | 型号 | 总线 | 作用 |
| --- | --- | --- | --- |
| 主控 | ESP32-S3-DevKitC-1 **N16R8** | — | 16MB Quad-SPI Flash + 8MB **Octal** PSRAM |
| 麦克风 | INMP441 | I2S0 (输入) | 数字 MEMS 麦克风 |
| 功放 | MAX98357A | I2S1 (输出) | 3W 数字功放 |
| 心率 | MAX30102 | I2C0 | 脉搏波 / 血氧 |
| 温度 | AS6221 | I2C1 | ±0.09℃ 高精度温度 |

## 几个必须知道的点

**1. 两条独立的 I2C 总线**

ESP32-S3 有两个 I2C 控制器，正好一条一个，互不干扰：

- `Wire`  → GPIO8/9   → MAX30102
- `Wire1` → GPIO10/11 → AS6221

所以这两组引脚**不能混接**，也不需要在同一条总线上协调地址。

**2. AS6221 的 ALT/ADD1 必须接 GND，不能悬空**

数据手册明确要求 `ADD0` **和** `ALERT/ADD1` 都不能悬空 —— 芯片地址由这两个脚共同决定。
悬空时地址是不确定的，可能碰巧扫到 0x48，也可能哪天漂到别处。

两个脚都接 GND → 地址固定 **0x48**。

固件里做了兜底：开机扫描整条 Wire1，接受 0x44~0x4B 的任意地址，所以就算漂了也能认回来。
但这只是保险，正确做法是把它接死。

**3. MAX30102 的 PART_ID / REV_ID 寄存器别记反**

- `PART_ID` 在 **0xFF**，值是 `0x15`
- `REV_ID`  在 **0xFE**，值是 `0x03`

这两个很容易记反（0xFE 看起来更像"第一个"）。固件里会打印出来自检。

**4. FIFO 实际出数率是 50Hz，不是 25Hz**

`SPO2_CONFIG = 0x2B` 解码出来是 **200 sps**（不是 100），配合 4 次平均 → FIFO 输出 **50Hz**。
代码里的高通滤波系数按这个速率推出来的实际截止频率是 ~1.0Hz。

**5. N16R8 的引脚限制**

GPIO26~37 **不可用**（26~32 给 Flash，33~37 给 Octal PSRAM）。
另外 GPIO0/3/45/46 是 strapping 脚，GPIO19/20 是 USB，GPIO43/44 是 UART0，GPIO48 是板载 RGB 灯。

本项目的引脚全部避开：4/5/6、15/16/17、8/9、10/11。

## 构建与烧录

PlatformIO：

```bash
pio run -t upload          # 编译并烧录
pio device monitor         # 串口监视 (921600)
```

`platformio.ini` 里默认串口是 `COM10`，**换成你自己的**：

```ini
upload_port = COM10
monitor_port = COM10
```

> 注意：一块 S3 开发板通常会枚举出**两个** COM 口 —— 一个是板载 USB 转串口芯片
> （CH343 / CP2102），一个是芯片**原生 USB**。它们是同一颗芯片的两个接口，不是两块板子。
> 烧录用转串口那个口比较稳。

## 串口菜单

烧录后打开串口，看到菜单后按键：

| 按键 | 功能 |
| --- | --- |
| `s` / `1` | 喇叭测试（1kHz 正弦 + 扫频） |
| `l` / `2` | 回环：录 5 秒 → 立刻回放 |
| `r` | 录 1 分钟，然后通过串口上传 PCM |
| `m` / `3` | MAX30102 心率（60 秒 CSV 流） |
| `t` / `4` | AS6221 温度（测 20 秒） |
| `+` / `-` | 麦克风增益 |
| `h` | 显示菜单 |

## 上位机工具 (`tools/`)

**`pulse.py` + `pulse.html` — 心率 + 体温实时网页**

固件把数据以 CSV 从串口吐出来，这个脚本一边读串口、一边在本地起一个 HTTP 服务。

```bash
python tools/pulse.py COM10
```

然后浏览器打开 **http://localhost:8765**，能看到脉搏波形、心率数字、温度趋势。
一轮 60 秒结束后会自动叫下一轮，所以页面会一直刷新，不用掐表。

串口协议（8 字段）：

```
D,<red>,<ir>,<ac>,<bpm>,<finger>,<beat>,<temp_mC>
```

- `bpm = -1` 表示还没测出来
- `temp_mC` 是毫摄氏度整数，`-100000` 表示 AS6221 不在线
- `D,BEGIN` / `D,END` 是起止标记

**`console.py` — 串口控制台**

复位板子、抓完整启动横幅、可选延时后发一个按键，输出同时打到屏幕和一个 UTF-8 日志文件。

```bash
python tools/console.py COM10 m 22 5      # 复位, 5 秒后发 'm', 观察 22 秒
python tools/console.py COM10 "" 8        # 不发按键, 只看启动
```

> 为什么要它：Windows 控制台是 GBK，直接看原始串口字节会把中文显示成乱码。
> 这个脚本先在 Python 里按 UTF-8 正确解码成字符串，再交给控制台按自己的编码输出。

**`record.py` — 录音上传**

配合固件的 `r` 命令，把 1 分钟 PCM 从串口收下来存成 WAV。

## 已知限制

- **没有自启动**：上电后固件停在菜单等按键，不会自动开始采集。要脱开电脑独立运行，需要改 `setup()` 直接进采集循环，并加上显示 / 电池 / 无线。
- **温度测的是板温，不是体温**：AS6221 紧挨着 MAX30102，而红外 LED 和主控都在发热。手指捏住读数会往上爬（热响应是真的），但绝对值偏高。要当体温用需要做热隔离或标定偏移。
- **心率算法是 bring-up 级别的**：自适应阈值 + 不应期，够用来看"传感器确实跟着脉搏动"，但不是正经的 HR/SpO2 算法，没做运动伪影抑制。
